# ALBUM-14 AWS deploy with Terraform: plan

Spec: [2026-11-22-album-14-aws-terraform-deploy.md](../specs/2026-11-22-album-14-aws-terraform-deploy.md)

Test command: `npm test`; also `npm run lint` and `npm run typecheck`. Tests use the in-memory test database (`lib/db/test-db.ts`) and an in-memory fake of the S3 calls; never the dev database or live AWS. Read `node_modules/next/dist/docs/` (proxy, server actions, cookies, standalone output) before writing Next.js code; this Next.js has breaking changes. No `terraform apply`, no AWS calls that create or change anything. Each task ends with its tests, lint and typecheck green, then a commit and push.

1. **Gate (app).** `lib/config.ts`: `deployEnv` (`DEPLOY_ENV`: `staging`, `production`, or unset) and `appPassword` per spec (deployed + missing/empty/under 12 chars throws naming `APP_PASSWORD`; local unset means no gate). `lib/auth/`: session token (sign and verify, HMAC-SHA256 keyed from `APP_PASSWORD` + `DEPLOY_ENV`, 90 days, timing-safe), `safeNext` redirect target, `gateDecision` pure function (spec § Where it runs: `/login` passes, redirect for pages, 401 otherwise, 503 deployed with no password, 403 deployed with no origin secret header), `loginLimiter` (10 failures per IP per 15 min, 15 min lock, IP from `CloudFront-Viewer-Address`), `requireSession()`. `proxy.ts` calls `gateDecision` and adds `X-Robots-Tag: noindex, nofollow` (also from `next.config.ts` headers if the proxy can't cover every response). `app/login/` page and server action (one-second pause on failure, messages per spec). Call `requireSession()` at the start of every server action in `app/**/actions.ts`. Set `prefetch={false}` on every `Link` in `app/` and `components/`, and add a test that fails on a `Link` without it. Tests per spec § Tests (session token, redirect target, gate decision, guessing limit, config, no prefetch), table-driven.
2. **S3 storage mode.** `lib/db/s3-sync.ts` (+ test): `DATABASE_S3_BUCKET`, `DATABASE_S3_KEY` config; cold start download to `DATABASE_PATH` (in `/tmp`), missing object creates and uploads an empty migrated database, invalid file (no `schema_migrations`) gives an error state and touches nothing, per-request ETag check with reload on change, after a request that changed the database (`total_changes` / `data_version`) write a `VACUUM INTO` copy and upload with `If-Match` (`If-None-Match: *` for the first upload) before the response ends, failed conditional write fails the request and drops the local copy. Skip the pre-migrate backup in this mode. Wire it through a small wrapper entry (`lambda/server.ts` or similar) around the Next.js standalone server; add `@aws-sdk/client-s3` as the one new runtime dependency. Tests against an in-memory fake S3 client, per spec § Tests. Local behavior unchanged when the two settings are unset.
3. **Packaging and Terraform.** `npm run build:lambda` (script under `scripts/`): `output: "standalone"` in `next.config.ts`, assemble `dist/lambda/` (server, `lib/db/migrations/`, wrapper, start script for the Lambda Web Adapter) and `dist/static/`, write `dist/build-info.json` with the commit. `infra/bootstrap/` (state bucket, versioned, encrypted, public access blocked), `infra/modules/app/` (every resource in spec § AWS components: Lambda arm64 Node 24 with reserved concurrency 1 and the Web Adapter layer, function URL, CloudFront with the assets and function origins and the secret origin header, data bucket versioned with 30-day noncurrent expiry and destroy protection, assets bucket, log group 14 days, IAM scoped to its own data bucket, optional budget, `random_password` for the password and origin secret, static file upload), `infra/envs/staging` and `infra/envs/production` (S3 backend with `use_lockfile`, `backend.hcl` and `terraform.tfvars` gitignored, `.example` files committed, `.terraform.lock.hcl` committed). Outputs: `url`, `password` (sensitive), `data_bucket`, deployed commit. `.gitignore` additions per spec § Terraform. Verify with `terraform fmt -check` and `terraform init -backend=false && terraform validate` for every root; run `terraform plan` only if AWS credentials are present and the plan is read-only, else list it under Not proven. Check the Node 24 Lambda runtime name, the Web Adapter layer ARN and version, and current prices against AWS docs, and report anything that contradicts the spec (the spec's `BLOCKED:` rule applies).
4. **Local run proof.** Run the packaged server locally (start script, a local S3 stand-in or the fake client) and check: no cookie redirects to `/login`, wrong password refused, right one lets in, a write survives a restart, a restore (replace the stored object) shows up on the next request. Keep the script or notes for the PR's Proof section; don't commit data files.
5. **Docs.** README "Deploy to AWS" section and `APP_PASSWORD` line in "Run the app" per spec § README; `.env.example` entries (`APP_PASSWORD`, `DEPLOY_ENV`, `DATABASE_S3_*`); `docs/stack.md` Hosting, Infrastructure and Auth rows (and the note about `requireSession()`); `docs/agents/project.md` § Environments and deploy.
